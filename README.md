# Дайджест ИТ-новостей (three-source-digest)

Лёгкая версия бота: собирает новости из **трёх источников** и присылает в тот же
Telegram-канал через того же бота.

Источники:
- CNews — `https://www.cnews.ru/inc/rss/news.xml`
- TAdviser — `https://www.tadviser.ru/xml/tadviser.xml`
- Новости ИТ-канала — `https://www.novostiitkanala.ru/rss`

Формат каждой новости:
```
🔹 Заголовок новости
Одна фраза сути (из описания RSS; если его нет — только заголовок)
Источник →   (ссылка)
```

Один пресс-релиз часто выходит сразу в двух лентах. Такие перепечатки бот
склеивает в один блок и перечисляет источники через `·`:
```
CNews → · НовостиИТ-канала →
```
Заголовки сравниваются нормализованными (без знаков и регистра), совпадение
считается от `DUPLICATE_RATIO` = 0.88, так что «Sense» и «SENSE» — одна новость.

В канал попадают **только новые** новости: бот помнит уже отправленное в файле
`seen.json`, поэтому одни и те же новости не приходят повторно.

## Как это устроено

- `news_bot.py` — весь код в одном файле, из внешних сервисов только Telegram.
- Загрузка лент: `requests`, а при сбое TLS — фолбэк на системный `curl`
  (нужно на старом macOS-Python; в GitHub Actions работает напрямую).
- «Одна фраза» берётся из описания RSS. Мусорные вики-ссылки TAdviser
  («Основная статья: …») и описания, дублирующие заголовок, отбрасываются.
- `seen.json` — список id уже отправленных новостей (хранится последних ~1500).
- Новости старше 3 дней игнорируются (защита от потопа).

### Тематический фильтр

Правила отсева живут в `news_filter.py`, бот вызывает их из `should_include()`.
Фильтр работает как чёрный список: новость проходит, пока не совпала с шаблоном
мусора — так незнакомая, но важная тема не потеряется.

Что отсекается: ERP и CRM целиком (решение владельца от 18.08.2026 — отдельное
направление, за которым он не следит), вузы и студенты,
HR, зарплатные обзоры и кадровый учёт, быт,
ЖКХ и частные лица, потребительское поведение и опросы населения, игры,
зарубежная политика и зарубежные вендоры потребительских ОС без российского
следа, рынки СНГ, потребительские устройства, сервисы и финансы, автомобили,
туризм и гостиницы, шеринг, крипта, азартные игры, маркетплейсы, БПЛА,
экосистемы «Яндекса» и VK, облака, телеком-покрытие и региональный PR
операторов, видеонаблюдение и городская среда, интервью и авторские колонки,
уголовная хроника. Разработки — программные и аппаратные — остаются.

Два правила отменяются контекстом: «зарубежная политика» и «зарубежные вендоры»
не срабатывают, если в тексте упомянута Россия (список в `RUSSIA_EXEMPT`).

У каждого правила две настройки:

- **где искать** — во всём тексте, в заголовке или в первом предложении заголовка.
  Неоднозначные слова («университет», «смартфон») ищутся только в заголовке:
  в описании они попадаются в новостях совсем на другую тему.
- **сила** — `HARD` отсекает всегда, `SOFT` только если рядом нет корпоративного
  маркера. Поэтому «предзаказ на смартфоны» уходит, а «поставка ноутбуков
  корпоративным клиентам» остаётся.

Проверить правила, ничего не отправляя:

```bash
python3 news_filter.py --check                  # прогон по живым лентам
python3 news_filter.py --test "заголовок"       # проверить один заголовок
python3 test_filter.py                          # тесты: мусор отсеян, полезное прошло
```

Отсеянное видно в логе GitHub Actions с указанием причины — по нему понятно,
какое правило сработало и надо ли его править. Если в дайджест просочилось
лишнее или пропало нужное — добавь случай в `test_filter.py` и поправь правило.

⚠️ Правка правил работает только после `git push`: бот запускается на серверах
GitHub и берёт код из ветки `main`, а не с твоей машины. Локальный прогон
`--dry-run` показывает новые правила, дайджест в Telegram — ещё старые.

## Запуск локально

```bash
pip install -r requirements.txt

# положить токен и chat_id в .env:
#   TELEGRAM_BOT_TOKEN=...
#   TELEGRAM_CHAT_ID=...

# посмотреть дайджест без отправки:
python3 news_bot.py --dry-run

# отправить в Telegram:
python3 news_bot.py
```

### Первый запуск: «засеять» память

Чтобы при старте не пришёл разом весь список за 3 дня, один раз пометьте всё
текущее как уже отправленное:

```bash
python3 news_bot.py --seed
```

После этого бот будет слать только то, что появится дальше.

## Автозапуск (GitHub Actions)

Расписание — дважды в день: **08:00 и 20:00 МСК** (`.github/workflows/daily-news.yml`).
Всё крутится на серверах GitHub — компьютер может быть выключен.

Чтобы заработало:
1. Смёржить ветку в `main` (планировщик Actions запускается только с ветки по умолчанию).
2. В настройках репозитория задать Secrets: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`.
3. Включить Actions.

Память об отправленном (`seen.json`) экшен коммитит обратно в репозиторий — так
состояние сохраняется между запусками, а заодно репозиторий остаётся активным
(GitHub не отключит расписание по «правилу 60 дней тишины»). Право записи для
экшена уже выставлено (`default_workflow_permissions: write`).

Ручной запуск — кнопка **Run workflow** во вкладке Actions.
